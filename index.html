Reproducing a bug locally

git clone --recursive https://github.com/davidbau/nethack-bugreport.git
cd nethack-bugreport
bash setup.sh                                       # build the recorder once
bash bugs/01-vault-guard-parkguard-newsym/repro.sh  # run a bug repro

Each repro.sh re-runs the session JSON through a freshly-built NetHack 5.0 recorder binary and asserts the expected error text appears in the captured output. Exit 0 = bug reproduced; exit 1 = upstream may have fixed it.

Visualizing a session in-browser

Open the session viewer and load any session via the file picker, or deep-link to a specific session with a URL like: 

tools/session-viewer/?session=bugs/07-polyself-light-delete-before-create/session.json#step=127

The #step fragment is read on load and rewritten as you scrub, so every frame has its own shareable URL.

The viewer shows each step's TTY frame as a colored 24×80 grid, plus the full keystream, seed, datetime, and .nethackrc used by the recorder. Pure HTML/JS — no build, no server-side, no JS port needed.

Filing a new bug

See the README for the workflow. Briefly: record a session, drop it into bugs/NN-slug/session.json, write a README + repro.sh + proposed-fix.patch, add a row to the table above.
